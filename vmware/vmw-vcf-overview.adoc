[role="lead"]
NetApp ONTAP se integra con VMware Cloud Foundation (VCF) para ofrecer una solución de almacenamiento unificado compatible con los protocolos de bloques, archivos y objetos. Las capacidades de multi-tenancy de ONTAP permiten a las organizaciones consolidar cargas de trabajo y simplificar la gestión, mientras proporcionan protección de datos y disponibilidad de clase empresarial. Este documento ofrece una visión general de VCF y cómo NetApp ONTAP puede usarse para mejorar las capacidades de almacenamiento dentro de un entorno VCF.



[[introduction]]
== Introducción

VCF permite a las organizaciones implementar y gestionar un entorno de nube privada con facilidad. De serie, ofrece máquinas virtuales, Kubernetes, contenedores y redes como servicio, y permite ampliar la oferta para incluir otros servicios como elementos del catálogo en un portal de autoservicio. Al aprovechar NetApp ONTAP como solución de almacenamiento dentro de VCF, las organizaciones pueden lograr una mayor flexibilidad, escalabilidad y eficiencia en la gestión de sus cargas de trabajo.



[[introduction-to-netapp-ontap]]
== Introducción a NetApp ONTAP

NetApp ONTAP es un software integral de gestión de datos que ofrece funciones avanzadas de almacenamiento en una amplia gama de productos. ONTAP está disponible como almacenamiento definido por software, como servicio propio a través de los principales proveedores de nube y como sistema operativo de almacenamiento para las plataformas NetApp ASA (desagregado para bloques optimizado), AFX (desagregado para datos no estructurados), AFF y FAS (unificadas). ONTAP ofrece alto rendimiento y baja latencia para una gran variedad de casos de uso, incluida la virtualización de VMware, sin crear silos. De forma similar a como se creaba una máquina virtual (VM) en el ámbito de la computación, ONTAP permite la creación de máquinas virtuales de almacenamiento (SVM) que pueden utilizarse para crear y gestionar recursos de almacenamiento. ONTAP ofrece una solución de almacenamiento unificado compatible con múltiples protocolos, entre ellos NFS, SMB, iSCSI, FC, NVMe/TCP, NVMe/FC y NVMe/RDMA. Esta flexibilidad permite a las organizaciones consolidar cargas de trabajo y simplificar la gestión, al tiempo que proporciona protección y disponibilidad de datos de clase empresarial.



[[introduction-to-vmware-cloud-foundation]]
== Introducción a VMware Cloud Foundation

VMware Cloud Foundation (VCF) permite a las organizaciones crear nubes privadas virtuales donde pueden consumir máquinas virtuales, clústeres de Kubernetes, contenedores, redes y almacenamiento como servicio, ya sea para cargas de trabajo de IA, DevOps o cargas de trabajo tradicionales basadas en máquinas virtuales.

VCF se implementa en entornos nuevos o para ampliar un entorno existente de vSphere a una nube privada completa. Un conjunto de hosts de cálculo forma un clúster de vSphere, un grupo de clústeres de vSphere forma un dominio VCF y un grupo de dominios VCF forma una instancia VCF. Una flota consta de una o más instancias de VCF. Los entornos privados de nube de VCF se crean utilizando una o más flotas. El funcionamiento y la automatización se gestionan a nivel de flota, mientras que la instancia de VCF es la unidad de implementación.

Se utiliza un espacio de nombres vSphere para establecer límites de recursos para las cargas de trabajo. Una zona vSphere es un conjunto de clústeres vSphere que se puede utilizar para proporcionar capacidades de alta disponibilidad y recuperación ante desastres para las cargas de trabajo que se ejecutan en la zona.

image:vmware-vcf-overview-components.png["Componentes de VMware Cloud Foundation"]

En VCF Automation, una región es un conjunto de zonas de vSphere de uno o más dominios VCF que comparten la misma infraestructura NSX. Una organización es una agrupación lógica de usuarios y recursos de una o más regiones. La organización puede subdividirse en varios proyectos, cada uno con su propio gateway de tránsito y conexión externa. Un proyecto tiene uno o más espacios de nombres y puede usarse para proporcionar aislamiento y asignación de recursos a las cargas de trabajo que se ejecutan en el proyecto.

Los espacios de nombres son la unidad fundamental para la asignación de recursos dentro de un proyecto. Cada espacio de nombres se asigna a una nube privada virtual (VPC) y puede utilizarse para proporcionar aislamiento y asignación de recursos a las cargas de trabajo que se ejecutan en dicho espacio de nombres.

Los espacios de nombres se crean con una VPC dedicada o una VPC compartida. Una VPC dedicada es una VPC exclusiva para un único espacio de nombres, mientras que una VPC compartida es una VPC que pueden utilizar varios espacios de nombres. Las subredes se crean dentro de una VPC donde se implementan las cargas de trabajo.

El almacenamiento lo consumen las políticas de gestión basada en políticas de almacenamiento (SPBM) definidas en vCenter. Las políticas SPBM pueden crearse mediante un conjunto de reglas que definen los requisitos de almacenamiento de una carga de trabajo. Normalmente, los almacenes de datos se etiquetan y se utilizan para crear políticas de almacenamiento que se adapten a las necesidades específicas de las diferentes cargas de trabajo.

Las cargas de trabajo que requieren reglas de afinidad y anti-afinidad se gestionan mediante políticas de infraestructura que utilizan políticas de computación de vCenter para definir la ubicación de las cargas de trabajo en hosts o clústeres específicos. Las políticas de infraestructura pueden usarse para garantizar que las cargas de trabajo se ubiquen en hosts o clústeres específicos según sus requisitos.



[[vcf-domains]]
== Dominios VCF

Los dominios son una construcción fundamental dentro de VCF que permite la organización de recursos en grupos distintos e independientes.  Los dominios ayudan a organizar la infraestructura de forma más efectiva, garantizando que los recursos se utilicen de manera eficiente.  Cada dominio se implementa con sus propios elementos de computación, red y almacenamiento.

image:vmware-vcf-overview-domains.png["Dominios de VMware Cloud"]

Hay dos tipos principales de dominios con VCF:

* *Dominio de gestión*: el dominio de gestión incluye componentes responsables de las funciones básicas del entorno VCF. Estos componentes se encargan de tareas esenciales como el aprovisionamiento de recursos, la supervisión y el mantenimiento, e incluyen integraciones con complementos de terceros, como NetApp ONTAP Tools for VMware. Los dominios de gestión pueden implementarse mediante el dispositivo de instalación de VCF (VCF Installer Appliance) para garantizar el cumplimiento de las mejores prácticas, o bien puede convertirse un entorno existente de vCenter en un dominio de gestión de VCF.
* *Dominio de carga de trabajo* – los dominios de carga de trabajo están diseñados como pools de recursos dedicados a una necesidad operativa, una carga de trabajo o una organización específicas. Los dominios de carga de trabajo se implementan fácilmente a través de OPS Manager, lo que ayuda a automatizar una serie de tareas complejas. Se pueden aprovisionar hasta 24 dominios de carga de trabajo en un entorno VCF, y cada uno representa una unidad de infraestructura lista para aplicaciones. Cada dominio de carga de trabajo tiene su propia infraestructura NSX o comparte una existente, dependiendo de si es una implementación de una sola región o de varias regiones.




[[storage-with-vcf]]
== Almacenamiento con VCF

Un aspecto central de la funcionalidad de los dominios es el almacenamiento que consumen.  Si bien VCF incluye capacidad vSAN basada en núcleos de CPU para casos de uso hiperconvergentes, también admite una amplia gama de soluciones de almacenamiento externo.  Esta flexibilidad es crucial para las empresas que tienen inversiones significativas en matrices de almacenamiento existentes o necesitan soportar protocolos más allá de los que vSAN ofrece.  VMware admite múltiples tipos de almacenamiento con VCF.

Hay dos tipos principales de almacenamiento con VCF:

* *Almacenamiento principal* – este tipo de almacenamiento se aprovisiona automáticamente como parte de la implementación del día 0 de un nuevo dominio VCF o como parte de la convergencia o importación de un vCenter existente. El instalador de VCF admite VSAN, VMFS sobre FC y NFS como parte de una implementación desde cero, mientras que otros tipos de almacenamiento compatibles, como VMFS sobre iSCSI y NVMe-oF, pueden configurarse como almacenamiento principal como parte de la convergencia o importación de un vCenter existente. ONTAP Tools for VMware vSphere solo puede utilizarse para la convergencia o importación de un vCenter existente para implementar el almacenamiento principal para un dominio VCF. Cualquier almacén de datos creado como parte de una implementación de clúster adicional o como parte de una ampliación del dominio se considera almacenamiento principal. El almacenamiento principal se utiliza para alojar los componentes de gestión de VCF, incluidos vCenter, NSX Manager y SDDC Manager, así como las cargas de trabajo que se ejecutan dentro del dominio.
* *Almacenamiento complementario* – el almacenamiento complementario es cualquier almacén de datos que se aprovisiona tras la implementación inicial de un dominio VCF o tras la convergencia o importación de un entorno vCenter ya existente. El almacenamiento complementario se puede crear mediante ONTAP Tools for VMware vSphere para implementar almacenes de datos en un dominio VCF. El almacenamiento complementario se crea para satisfacer necesidades de capacidad adicionales, requisitos de rendimiento o para dar soporte a cargas de trabajo específicas que requieren características de almacenamiento diferentes. El almacenamiento complementario también se puede crear para crear clústeres extendidos y así lograr alta disponibilidad.

[[why-ontap-for-vcf]]
== ¿Por qué ONTAP para VCF?

Además de los casos de uso que involucran protección de inversiones y soporte de múltiples protocolos, existen muchas razones adicionales para aprovechar el almacenamiento compartido externo dentro de un dominio de carga de trabajo VCF.  Se puede suponer que el almacenamiento provisto para un dominio de carga de trabajo es simplemente un repositorio para alojar máquinas virtuales y contenedores.  Sin embargo, las necesidades de la organización a menudo superan las capacidades de la licencia y requieren almacenamiento empresarial.  El almacenamiento proporcionado por ONTAP, asignado a dominios dentro de VCF, es fácil de implementar y ofrece una solución de almacenamiento compartido a prueba de futuro.

image:why-ontap-for-vmware-002.png["¿Por qué ONTAP para VCF?"]

Para obtener más información sobre los principales beneficios de ONTAP para VMware VCF identificados a continuación, consultelink:vmw-getting-started-overview.html#why-ontap-for-vmware["¿Por qué ONTAP para VMware?"] .

* Flexibilidad desde el primer día y a medida que escala
* Descargue tareas de almacenamiento a ONTAP
* La mejor eficiencia de almacenamiento de su clase
* Disponibilidad de datos de nivel empresarial
* Operaciones de respaldo y recuperación eficientes
* Capacidades de continuidad empresarial holísticas

[[summary]]
== Resumen

ONTAP proporciona una plataforma que aborda todos los requisitos de carga de trabajo, ofreciendo soluciones de almacenamiento en bloque personalizadas y ofertas unificadas para permitir resultados más rápidos para máquinas virtuales y aplicaciones de manera confiable y segura.  ONTAP incorpora técnicas avanzadas de reducción y movimiento de datos para minimizar el espacio ocupado por el centro de datos, al tiempo que garantiza la disponibilidad a nivel empresarial para mantener las cargas de trabajo críticas en línea.  Además, AWS, Azure y Google admiten el almacenamiento externo impulsado por NetApp para mejorar el almacenamiento vSAN en clústeres basados en la nube de VMware como parte de sus ofertas de VMware-in-the-Cloud.  En general, las capacidades superiores de NetApp lo convierten en una opción más efectiva para las implementaciones de VMware Cloud Foundation.

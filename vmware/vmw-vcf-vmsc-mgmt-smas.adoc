= Configura un clúster extendido para un dominio de gestión VCF usando SnapMirror Active Sync (SAN y NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
En este caso de uso, describimos el procedimiento para utilizar las ONTAP tools for VMware vSphere para configurar un clúster extendido para un dominio de administración de VCF.  Este procedimiento incluye la implementación de hosts vSphere y vCenter Server, la instalación de herramientas ONTAP , la protección de almacenes de datos con SnapMirror Active Sync, la migración de máquinas virtuales a almacenes de datos protegidos y la configuración de almacenamiento complementario.

image:vmw-vcf-vmsc-mgmt-smas-001.png["Clúster extendido con ONTAP para el dominio de administración de VCF"]

Se admiten tanto configuraciones en clústeres extendidos uniformes como no uniformes para SAN. En el caso de NAS, es una configuración activa-pasiva con ONTAP 9.19.1.

[NOTE]
====
Los parámetros de proximidad del host se utilizan junto con la configuración multivía para garantizar la selección óptima de la ruta para el tráfico de almacenamiento. Los parámetros de proximidad del host se configuran en igroup en el caso de SCSI y en subsystem en el caso de NVMe-oF. Por ejemplo, en la configuración de acceso uniforme al host, el host tiene acceso a ambos sistemas de almacenamiento en el clúster extendido. En la configuración multivía, las rutas óptimas y no óptimas se configuran en función de los parámetros de proximidad del host.

====


[[scenario-overview]]
== Descripción general del escenario

La solución de clúster extendido puede implementarse en un clúster predeterminado o en un clúster adicional en los dominios de gestión o de cargas de trabajo de VCF. ONTAP tools 10.6 admite la protección de almacenes de datos con SnapMirror active sync para almacenes de datos VMFS en los protocolos iSCSI y FC. ONTAP admite SnapMirror active sync para SAN (con iSCSI, FC, NVMe-oF) y NAS (NFS v3 y NFSv4.1). Para los protocolos SAN, la protección se realiza a nivel de grupo de consistencia, mientras que para NAS se realiza a nivel de SVM. El siguiente diagrama ilustra la solución de clúster extendido para un dominio de gestión VCF con ONTAP tools para VMFS con FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["Clúster extendido con ONTAP para el dominio de administración de VCF"]

.Almacenamiento principal en el dominio de administración
[%collapsible%open]
====
. Implementa el dominio de gestión de VCF con cualquier protocolo compatible.
+
.. Para VMFS en FC y NFSv3, se utiliza directamente la herramienta VCF Installer. En el caso de iSCSI, NVMe-oF y NFSv4.1, necesitas configurarlo con vCenter y luego usar la herramienta VCF Installer para desplegar el dominio de gestión. Para más información, consulta link:vmw-vcf-migrate.html["Implementación del dominio de gestión de VCF con iSCSI, NVMe-oF y NFSv4.1"]


. Implementar ONTAP tools for VMware vSphere
. Implementar el complemento SnapCenter para VMware vSphere (opcional)
. Protege el almacén de datos.
+
.. Para iSCSI y FC, se usan ONTAP tools 10.6 o superior para proteger los datastores. En caso de NVMe-oF y NFSv4.1, utiliza system manager para proteger los datastores. Como referencia, revisa el video demo de abajo para NVMe/TCP y NFS.




====
.Almacenamiento complementario en el dominio de administración
[%collapsible%open]
====
Una vez que el dominio de gestión está en funcionamiento, puedes crear almacenes de datos adicionales usando ONTAP tools 10.6 o superior y protegerlos con SnapMirror active sync para iSCSI y FC. Para NVMe-oF y NFS, revisa el video de demostración a continuación como referencia, ya que la demo se realiza en un dominio de carga de trabajo, pero puedes seguir los mismos pasos también para el dominio de gestión.

====

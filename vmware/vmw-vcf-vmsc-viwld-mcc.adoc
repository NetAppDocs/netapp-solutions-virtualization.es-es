[role="lead"]
En este caso de uso describimos el procedimiento para configurar un clúster stretch para el dominio de cargas de trabajo de VMware Cloud Foundation (VCF) utilizando ONTAP MetroCluster con FC, iSCSI, NVMe-oF, NFSv3 o NFSv4.1 como almacén de datos principal. VCF ofrece flexibilidad en las opciones de implementación según tus necesidades. La herramienta VCF Ops se usa para implementar un nuevo dominio de carga de trabajo de VCF o importar un entorno existente de vSphere a un dominio de carga de trabajo de VCF. En este documento, nos vamos a centrar en la parte de MetroCluster y te indicaremos otra documentación según los pasos de implementación.

image:vmw-vcf-vmsc-viwld-mcc-001.png["Dominio de carga de trabajo VCF con vMSC, width=500"]



[[introduction]]
== Introducción

En esta solución vamos a mostrar cómo implementar Stretched VCF Workload Domain con ONTAP MetroCluster como principal datastore. MetroCluster permite implementar una solución de alta disponibilidad para todas las cargas de trabajo que se ejecutan en el clúster de ONTAP. Si necesitas implementar una solución de alta disponibilidad específica para cargas de trabajo, considera usar SnapMirror active sync (SAN y NAS). SnapMirror active sync (SAN) funciona a nivel de grupo de consistencia, mientras que SnapMirror active sync (NAS) funciona a nivel de SVM. Para más información, consulta link:vmw-vcf-vmsc-viwld-smas.html["Configura un clúster extensible para un dominio de carga de trabajo VCF usando SnapMirror Active Sync (SAN y NAS)"].



[[prerequisites]]
== Prerrequisitos

Este escenario requiere los siguientes componentes y configuraciones:

* Configuración de ONTAP MetroCluster compatible
* Máquina virtual de almacenamiento (SVM) configurada con el protocolo de almacenamiento preferido.
* Se ha creado una interfaz lógica (LIF) para transportar tráfico de almacenamiento y está asociada a la SVM.

[[deployment-steps-for-greenfield-vcf-workload-domain-with-metrocluster]]
== Pasos para la implementación de un dominio de carga de trabajo VCF Greenfield con MetroCluster

Para una implementación Greenfield (una nueva implementación sin ningún componente VCF preexistente), se utiliza la herramienta VCF Ops para implementar el dominio de carga de trabajo. VMFS sobre FC y NFSv3 son compatibles en este escenario.

En el caso de VMFS sobre FC, consulta link:vmw-vcf-viwld-principal-fc.html["Dominio de carga de trabajo VCF con un almacén de datos VMFS basado en FC en ONTAP como almacenamiento principal"] para obtener más información. Para NFSv3, consulta link:vmw-vcf-viwld-principal-nfs.html["Dominio de carga de trabajo VCF con un datastore NFSv3 en ONTAP como almacenamiento principal"] para obtener más información.



[[deployment-steps-for-brownfield-vcf-workload-domain-with-metrocluster]]
== Pasos para la implementación del dominio de carga de trabajo VCF brownfield con MetroCluster

Una implementación en entorno preexistente es un caso en el que tienes un entorno vSphere existente y quieres importarlo como un dominio de carga de trabajo VCF.

Para iSCSI, NVMe-oF y NFSv4.1, necesitas configurarlo con vCenter (preferiblemente con ONTAP tools) y luego usar la herramienta VCF Ops para importarlo como un dominio de carga de trabajo. Para más información, consulta link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/import-an-existing-vcenter-to-create-a-workload-domain.html["Importa un vCenter existente para crear un Workload Domain"].

= Configura un clúster extensible para un dominio de carga de trabajo usando la sincronización activa de SnapMirror (SAN y NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
En este caso de uso te mostramos el procedimiento para configurar un clúster extendido para un dominio de carga de trabajo usando SnapMirror active sync con ONTAP tools for VMware vSphere (ONTAP tools 10.6 es compatible con FC e iSCSI). ONTAP admite SnapMirror active sync tanto para SAN (con iSCSI, Fibre Channel y NVMe over Fabrics) como para NAS (NFSv3 y NFSv4.1).

image:vmw-vcf-vmsc-viwld-smas-001.png["Stretch cluster para VCF con sincronización activa de SnapMirror"]

Se admiten tanto configuraciones en clústeres extendidos uniformes como no uniformes para SAN. En el caso de NAS, es una configuración activa-pasiva con ONTAP 9.19.1.

[NOTE]
====
Los parámetros de proximidad del host se utilizan junto con la configuración multivía para garantizar la selección óptima de la ruta para el tráfico de almacenamiento. Los parámetros de proximidad del host se configuran en igroup en el caso de SCSI y en subsystem en el caso de NVMe-oF. Por ejemplo, en la configuración de acceso uniforme al host, el host tiene acceso a ambos sistemas de almacenamiento en el clúster extendido. En la configuración multivía, las rutas óptimas y no óptimas se configuran en función de los parámetros de proximidad del host.

====


[[scenario-overview]]
== Descripción general del escenario

Los almacenes de datos del dominio de carga de trabajo de VCF pueden protegerse con la sincronización activa de SnapMirror para ofrecer una solución de clúster extendido. La protección se habilita a nivel de almacén de datos (grupo de consistencia) para SAN y se protege a nivel de SVM para NAS.



[[prerequisites]]
== Prerrequisitos

.Almacenamiento principal en el dominio de carga de trabajo
[%collapsible%open]
====
El dominio de carga de trabajo se puede crear ya sea mediante importación o mediante la creación usando la herramienta VCF Ops.

. Crea un dominio de carga de trabajo con cualquier protocolo compatible.
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-vcenter.html["Registrar el dominio de carga de trabajo vCenter en el administrador de herramientas de ONTAP para implementar el complemento vCenter"]
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-storage-backend.html["Registrar sistemas de almacenamiento en las herramientas ONTAP"]
. Para los almacenes de datos iSCSI y FC, consulta link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/protect/protect-multiple-ds.html["Protege el datastore de vSphere con las herramientas de ONTAP"]
. Para los almacenes de datos NVMe-oF y NFS, mira el vídeo de demostración a continuación para ver los pasos para proteger los almacenes de datos en el dominio de carga de trabajo con SnapMirror active sync.


====
.Almacenamiento complementario en el dominio de carga de trabajo
[%collapsible%open]
====
Una vez que el dominio de carga de trabajo esté en funcionamiento, se pueden crear y proteger almacenes de datos adicionales mediante las herramientas de ONTAP. Para obtener más detalles sobre SnapMirror active sync, consulta https://docs.netapp.com/us-en/ontap/snapmirror-active-sync/index.html#benefits["Conoce la sincronización activa de ONTAP SnapMirror"]


TIP: Con ONTAP tools 10.6 y versiones posteriores, puedes proteger los datastores del dominio de carga de trabajo con SnapMirror active sync. Consulta el video de demostración a continuación para ver los pasos para proteger los datastores del dominio de carga de trabajo con SnapMirror active sync.

====

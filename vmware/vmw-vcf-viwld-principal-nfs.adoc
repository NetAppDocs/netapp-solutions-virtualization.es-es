= Usa un almacén de datos NFS en ONTAP como almacenamiento principal para un dominio de carga de trabajo de VCF
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
En este caso de uso describimos el procedimiento para configurar un almacén de datos NFS en ONTAP como solución de almacenamiento principal para un dominio de carga de trabajo de VMware Cloud Foundation (VCF). Este procedimiento resume los componentes necesarios, los pasos de configuración y el proceso de implementación.



[[benefits-of-nfs]]
== Beneficios de NFS

*Simplicidad y facilidad de uso:* NFS es fácil de configurar y administrar, lo que lo convierte en una excelente opción para entornos que requieren compartir archivos de manera rápida y sencilla.

*Escalabilidad:* La arquitectura de ONTAP permite que NFS escale de manera eficiente, soportando las crecientes necesidades de datos sin cambios significativos en la infraestructura.

*Flexibilidad:* NFS admite una amplia gama de aplicaciones y cargas de trabajo, lo que lo hace versátil para diversos casos de uso, incluidos entornos virtualizados.



[[scenario-overview]]
== Descripción general del escenario

Este escenario cubre los siguientes pasos de alto nivel:

* Cree una máquina virtual de almacenamiento (SVM) con interfaz lógica (LIF) para el tráfico NFS
* Verifique la red para la máquina virtual de almacenamiento ONTAP (SVM) y que haya una interfaz lógica (LIF) presente para transportar tráfico NFS.
* Crea una política de exportación para permitir que los hosts de vSphere accedan al volumen NFS.
* Cree un volumen NFS en el sistema de almacenamiento ONTAP .
* Cree un grupo de redes para el tráfico NFS y vMotion en SDDC Manager.
* Comisiona hosts en vCenter para usarlos en un dominio de carga de trabajo de VCF.
* Implementa un dominio de carga de trabajo de VCF en VCF Ops usando un almacén de datos NFS como almacenamiento principal.
* Asegúrate de que la imagen del clúster incluya el complemento NFS de NetApp para VMware VAAI.



NOTE: Esta solución es aplicable a las plataformas ONTAP compatibles con almacenamiento NFS, entre las que se incluyen NetApp AFF, AFX y FAS.



[[prerequisites]]
== Prerrequisitos

En este escenario se utilizan los siguientes componentes y configuraciones:

* NetApp sistema de almacenamiento AFF, AFX o FAS con una máquina virtual de almacenamiento (SVM) configurada para permitir el tráfico NFS.
* Se ha creado una interfaz lógica (LIF) en la red IP que transportará el tráfico NFS y está asociada con la SVM.
* La implementación del dominio de gestión de VCF ha finalizado y la interfaz de VCF Operations Manager es accesible.
* Al menos 2 hosts vSphere configurados para la comunicación en la red de gestión de VCF.
* Direcciones IP reservadas para el tráfico de almacenamiento vMotion y NFS en la VLAN o segmento de red establecido para este propósito.



NOTE: Al implementar un dominio de carga de trabajo de VCF, VCF comprueba la conectividad con el servidor NFS. Esto se lleva a cabo mediante el adaptador de gestión en los hosts vSphere antes de que se añada cualquier adaptador vmkernel adicional con la dirección IP del NFS. Por lo tanto, es necesario asegurarse de que 1) la red de gestión sea enrutable hacia el servidor NFS, o 2) se haya añadido un LIF para la red de gestión al SVM que aloja el volumen del almacén de datos NFS, para garantizar que la validación pueda continuar.

Para obtener información sobre la configuración de los sistemas de almacenamiento ONTAP , consultelink:https://docs.netapp.com/us-en/ontap["Documentación de ONTAP 9"] centro.

Para obtener información sobre cómo configurar VCF, consulta link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["Documentación de VMware Cloud Foundation"].

Para obtener más información sobre el uso de NFS con clústeres de vSphere, consulte lalink:vmw-vvf-overview.html["Guía de referencia de NFS v3 para vSphere 8"] .

[[deployment-steps]]
== Pasos de implementación

Para implementar un dominio de carga de trabajo de VCF con un almacén de datos NFSv3 como almacenamiento principal, completa los siguientes pasos:

.Verificar la red para ONTAP SVM
[%collapsible%open]
====
Comprueba que se hayan establecido las interfaces lógicas necesarias para la red que transportará el tráfico NFS entre el clúster de almacenamiento ONTAP y Workload Domain.

. Desde ONTAP System Manager, navega a *Storage VMs* en el menú de la izquierda y haz clic en la SVM que se va a usar para el tráfico NFS. En la pestaña *Overview*, debajo de *Network interfaces*, haz clic en el número que aparece encima de la etiqueta *NFS*. En la lista, verifica que las direcciones IP de LIF necesarias estén incluidas.
+
image:vmw-vcf-viwld-principal-nfs-001.png["Verifica las LIF de NFS para SVM"]



Como alternativa, verifique los LIF asociados con una SVM desde la CLI de ONTAP con el siguiente comando:

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. Comprueba que los hosts vSphere puedan comunicarse con el servidor NFS de ONTAP. Inicia sesión en el host vSphere a través de SSH y haz ping a la LIF de la SVM:


[source, cli]
----
vmkping <IP Address>
----

NOTE: Al implementar un dominio de carga de trabajo, VCF comprueba la conectividad con el servidor NFS. Esto se lleva a cabo mediante el adaptador de gestión en los hosts vSphere antes de que se añada cualquier adaptador vmkernel adicional con la dirección IP de NFS. Por lo tanto, es necesario asegurarse de que 1) la red de gestión sea enrutable hacia el servidor NFS, o 2) se haya añadido una LIF para la red de gestión al SVM que aloja el volumen del datastore NFS, para garantizar que la validación pueda continuar.

====
.Crear una política de exportación para compartir un volumen NFS
[%collapsible%open]
====
Cree una política de exportación en ONTAP System Manager para definir el control de acceso para volúmenes NFS.

. En el Administrador del sistema ONTAP , haga clic en *Máquinas virtuales de almacenamiento* en el menú de la izquierda y seleccione una SVM de la lista.
. En la pestaña *Configuración*, busque *Políticas de exportación* y haga clic en la flecha para acceder.
+
image:vmw-vcf-viwld-principal-nfs-002.png["Políticas de exportación de acceso"]

+
{nbsp}

. Después de hacer clic en Add, se abrirá la ventana *New export policy*. Agrega un nombre para la política, haz clic en el botón *Add new rules* y luego en el botón *+Add* para empezar a agregar una nueva regla.
+
image:vmw-vcf-viwld-principal-nfs-003.png["Nueva política de exportación"]

+
{nbsp}

. Introduce las direcciones IP, el rango de direcciones IP o la red que desees incluir en la regla. Desmarca las casillas *SMB/CIFS* y *FlexCache* y selecciona los detalles de acceso que aparecen a continuación. Basta con marcar las casillas de UNIX para permitir el acceso a un host vSphere.
+
image:vmw-vcf-viwld-principal-nfs-004.png["Guardar nueva regla"]

+

NOTE: Al implementar un dominio de carga de trabajo, VCF comprueba la conectividad con el servidor NFS. Esto se lleva a cabo mediante el adaptador de gestión de los hosts vSphere antes de que se añada cualquier adaptador vmkernel adicional con la dirección IP de NFS. Por lo tanto, es necesario asegurarse de que la política de exportación incluya la red de gestión de VCF para que la validación pueda continuar.

. Una vez ingresadas todas las reglas, haga clic en el botón *Guardar* para guardar la nueva Política de exportación.
. Alternativamente, puede crear políticas y reglas de exportación en la CLI de ONTAP .  Consulte los pasos para crear una política de exportación y agregar reglas en la documentación de ONTAP .
+
** Utilice la CLI de ONTAP paralink:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["Crear una política de exportación"] .
** Utilice la CLI de ONTAP paralink:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["Agregar una regla a una política de exportación"] .




====
.Crear volumen NFS
[%collapsible%open]
====
Cree un volumen NFS en el sistema de almacenamiento ONTAP para usarlo como almacén de datos en la implementación del dominio de carga de trabajo.

. Desde el Administrador del sistema ONTAP , navegue a *Almacenamiento > Volúmenes* en el menú de la izquierda y haga clic en *+Agregar* para crear un nuevo volumen.
+
image:vmw-vcf-viwld-principal-nfs-005.png["Añadir nuevo volumen"]

+
{nbsp}

. Agregue un nombre para el volumen, complete la capacidad deseada y seleccione la máquina virtual de almacenamiento que alojará el volumen.  Haga clic en *Más opciones* para continuar.
+
image:vmw-vcf-viwld-principal-nfs-006.png["Agregar detalles de volumen"]

+
{nbsp}

. En Permisos de acceso, seleccione la Política de exportación que incluye la red de administración de VCF o la dirección IP y las direcciones IP de la red NFS que se utilizarán tanto para la validación del servidor NFS como para el tráfico NFS.
+
image:vmw-vcf-viwld-principal-nfs-007.png["Agregar detalles de volumen"]

+
+ {nbsp}

+

NOTE: Al implementar un dominio de carga de trabajo de VCF, VCF comprueba la conectividad con el servidor NFS. Esto se lleva a cabo mediante el adaptador de gestión en los hosts vSphere antes de que se añada cualquier adaptador vmkernel adicional con la dirección IP del NFS. Por lo tanto, es necesario asegurarse de que 1) la red de gestión sea enrutable hacia el servidor NFS, o 2) se haya añadido un LIF para la red de gestión al SVM que aloja el volumen del almacén de datos NFS, para garantizar que la validación pueda continuar.

. Como alternativa, los volúmenes NFS se pueden crear en la CLI de ONTAP. Para más información, consulta el comando link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["crear volumen"] en la documentación de comandos de ONTAP.

[[vcf-workload-domain-default-cluster]]
=== Dominio de carga de trabajo de VCF - Clúster predeterminado

Una vez que el dominio de gestión esté en funcionamiento, puedes crear el dominio de carga de trabajo de VCF:

* Usando la interfaz de usuario de VCF Ops. Los hosts vSphere se incorporan en vCenter y se configura el grupo de red. Usa System Manager o la API de ONTAP para exportar el volumen NFS a los hosts vSphere.
* Importa un entorno existente de vSphere como nuevo dominio de carga de trabajo. ONTAP tools for VMware vSphere, System Manager o la API de ONTAP se pueden usar para implementar el datastore NFSv3 o NFS4.1 en el clúster vSphere.




[[vcf-workload-domain-additional-cluster]]
=== VCF Workload Domain: clúster adicional

Para ampliar el dominio de carga de trabajo con un clúster adicional, consulta https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["Agrega un clúster SDDC a un dominio VCF"].

A grandes rasgos, los pasos para añadir un clúster adicional al dominio de carga de trabajo son los siguientes: * Asegúrate de que los hosts estén puestos en servicio y de que los grupos de red estén configurados en vCenter. * El volumen NFS se aprovisiona en el sistema de almacenamiento ONTAP y se exporta a los hosts del clúster adicional. * El volumen NFS se monta en uno de los hosts vSphere del clúster adicional. * Crea un nuevo clúster SDDC en el dominio de carga de trabajo en vCenter y sigue el asistente para añadir el clúster adicional al dominio de carga de trabajo.
